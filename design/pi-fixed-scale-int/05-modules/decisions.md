# pi-fixed-scale-int · 决定与来源（L5 返工）

## 可行性与选型

- 用户要求两套方法：普通版与正确舍入版，均不接受 f64 中间计算；选择纯 Rust `astro-float 0.9.6`，作为 `math` feature 的可选依赖，利用有向舍入计算上下界。核心整数 API 与 math 解耦；本机默认工具链 `cargo test --features math` 和 x64 MSVC 全特性测试已通过已覆盖的代表性样例。样例通过不是任意输入的全域证明；严格版无法确认时必须显式返回 PrecisionExhausted。
- 拒绝直接 f64：64 位原始计数附近丢失低位，不能证明正确舍入；拒绝 MPFR 原生依赖：用户明确要求纯 Rust、可选 feature。
- 严格版起始精度 192 bit，普通版 128 bit，逐次加倍到当前上限 12288 bit；仅在区间端点量化相同才返回严格结果，普通版在端点差至多 1 raw 且未越界时允许返回下界。上限耗尽则报 PrecisionExhausted，不默默降级。
- serde 1 与 fory 1.7.7 依现有 feature 单独可选，派生数值的 raw 字段往返。选择买成熟依赖而非自造协议；不承诺两者字节格式互通。当前默认 32 位工具链启用 fory 存在上游编译限制，x64 MSVC 全特性已通过。
- Cargo.toml 声明依赖版本；本工作区 Cargo.lock 锁定当前解析结果，作为库的消费者仍依其解析策略选择兼容版本。升级高精度库时复核边界、两档精度、错误分支及全特性组合，不凭单个样例宣称数学保证。

## 审查核验与依据

- 起始精度 128/192 bit 只影响通常路径开销，不作为误差证明；逐次加倍到 12288 bit 是资源上限而非正确性凭据。单次固定精度与 f64 不能保证近舍入分界值的正确性；上限用尽显式失败。尚无吞吐量基准。
- 普通档只在上下界分别量化后相差最多 1 raw 且都在范围内时取下界；区间真正包住数学真值是此误差保证和严格保证的共同前提。选下界是确定性策略，不主张更接近数学真值；若封闭性前提未证实则两档保证都不能声称成立。
- 已核对依赖的正确舍入合同与方向语义，有限、正常完成的计算可按 07-design/call-chain.md 的组合论证保持封闭上下界；指数范围耗尽、NaN/资源错误及失败传播须单独设防，不得用有限值论证覆盖这些路径。现有样例通过不是全域证明。
- 额外公开常量 75600、324000、2268000、9601200 当前没有明确的需求/消费者记录。只登记公开面待确认，不反向编造需求或在文档更新时擅自删生产代码。

### 可复核的依赖证据

核对版本为 astro-float 0.9.6 / astro-float-num 0.3.7，适用于本工作区 Cargo.lock 解析版本。

| 证据 | 已确认事实 | 使用前提 |
|---|---|---|
| astro-float 0.9.6 src/lib.rs:19–25、45–48；https://docs.rs/astro-float/0.9.6/astro_float/#introduction | 算术、数学函数、进制转换和常量均按指定模式正确舍入 | 依赖自身实现满足其公开合同；不把该承诺解释为本项目所有组合已自动正确 |
| astro-float-num 0.3.7 src/defs.rs:184–204 与 src/mantissa/mantissa.rs:1056–1075 | 虽然枚举注释措辞是 round half，底层 Up 在正数有非零舍弃位时进位、Down 在负数有非零舍弃位时增绝对值；两者实际为朝正/负无穷 | 对有限正常结果用 Down/Up 才能构造向外区间；不用 None 模式 |
| astro-float-num 0.3.7 src/conv.rs:619–639 | 十进制转换中 Up/Down 的方向规则一致 | 本库最终 raw 量化不通过十进制或 f64，中间值不受文本转换影响 |

上述源文件随 crates.io 包发布，可在注册表缓存或 docs.rs 对应源码定位；不依赖本地用户目录作为唯一证据源。无需本机再跑实现测试才能判断单调性，但后续实现验收必须有异常值、半值、范围和精度耗尽测试。

## 范围与防御

新数学功能不改变固定 u32 分母、64 位计数存储、同类型同分母加减或显式换分母的约定。定义域/越界/精度/计算失败各自可判断，失败后原值不变；math 方法不做 IO、持久化与隐式精度变更。
